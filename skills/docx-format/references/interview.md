# Interviews at decision points

First inspect; then propose. Do not ask a long generic questionnaire before
using evidence already present in the supplied files.

## Plan confirmation

Show the input roles, chosen document family, rule sources, likely content/
structure changes, preserved regions and material uncertainties. Recommend a
specific choice and explain its visible effect. Bundle related questions.

Examples:

- “模板有两种正文行距，我建议按格式说明的 1.5 倍执行，封面保持原样。”
- “表格前两行共同组成表头，三线表分隔线将放在第二行下方。”
- “模板红头是另一单位；沿用效果并替换已确认机关名称，还是保留原稿红头？”
- “正文从第 1 页重新编号需要分节；这属于结构调整，是否包含在本次范围？”

The user need not decide XML details. Do not re-ask explicit decisions. Preserve
unknown regions when they can safely remain untouched. If a required decision
is unanswered, keep dependent work pending and continue independent inspection.

## Sample confirmation

For batches, group by layout and object complexity. Inspect the automatic family
suggestions; they are not semantic proof. A single simple document cannot cover
different thesis, landscape-table and graphic-letterhead families.

Show an editable sample, changed areas and a preview when available. For special
letterheads show both a close view and the whole first page. Record the review
method honestly; structure-only approval is not visual validation.

## Final revision approval

Sample approval authorizes further review production, not acceptance. Ask the
user to review the actual output and bind acceptance to that version/file set.
Partial acceptance and rejection are valid outcomes. Keep original history.

Helpers record confirmation text but cannot establish human identity. The agent
must obtain the actual answer in conversation; it must never invent approval to
pass a command gate. Re-plan material changes and re-confirm affected scope.
